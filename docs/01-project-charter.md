# 项目章程

## 项目愿景

把 ChatGPT 官网相关图片能力整理成一个可自托管、可维护、可接入的 OpenAI 兼容图片服务与账号池系统，同时保留网页工作台、导入、刷新、同步和运维能力。

## 目标用户

- 自托管部署的站长或运维人员
- 需要图片生成 / 图片编辑兼容接口的集成方
- 需要维护账号池、代理、导入和同步链路的操作者
- 需要在网页端完成账号查看、刷新、筛选和编辑的人

## 最终完成态

项目进入完成态时，应至少满足：

- 图片生成、图片编辑、模型列表、工作台可稳定使用
- 账号池状态准确，刷新、重登、删除、导入链路清楚
- 额度、限流、未知额度、真无限额的语义一致
- Panda / 其他上游同步链路可控，失败可追踪
- 关键操作有测试和可验证的命令结果
- 文档足够清晰，后续 AI 可以按文档接手

## 成功标准

- 主要接口稳定：`/v1/images/generations`、`/v1/images/edits`、`/v1/chat/completions`、`/v1/responses`、`/v1/models`
- 账号池可维护：能筛选、刷新、删除、导入、导出、恢复异常账号
- 额度显示可信：不会把“未知”误写成“无限”
- 工程可验证：改动后有对应测试或构建结果
- 维护可交接：`docs/` 是固定入口，不依赖聊天记录

## 明确不做

- 不把这个项目定位成完整通用的 OpenAI 全量代理
- 不把它做成商业 SaaS 或代运营平台
- 不默认承担任何违反服务条款、滥用或批量滥发用途
- 不在日志中明文暴露密钥、令牌和敏感凭据
- 不为了省事而跳过验证直接下结论

## 长期质量底线

- 关键链路必须有测试覆盖
- 代码、配置和文档不能长期互相打架
- 生产链路改动要能回溯、能定位、能回滚
- 维护文档必须随事实更新
- 任何不确定项必须显式标记为“待确认”
