DB 在 315 秒变 error 后，底层 handler/curl 线程仍存活超过 12 分钟；进程曾有 13 个线程，其中约 5 个为历史 hard timeout 后遗留，网络命名空间存在指向 Webshare 的 `ESTABLISHED/CLOSE_WAIT`。

NewAPI 502 链路确认：

```text
NewAPI 普通同步请求
-> run_generation_sync() 等 Panda task
-> Panda task hard-timeout status=error
-> build_openai_image_response() 抛 RuntimeError
-> _image_error_response() 映射 HTTP 502
```

因此 502 是 Panda 终态错误映射，不是 NewAPI 独立 315 秒定时器。

### 修复实现

- `services/openai_backend_api.py`
  - ready predicate 改为真实 `conversation_id` metadata。
  - control heartbeat 不解除 pre-ready deadline，也不延长 post-ready 15 秒 deadline。
  - 新增 `ImageStreamCancelledError`、cancel-aware queue reader 与 poll sleep。
  - post-ready 到期非阻塞 abort SSE 并转现有轮询。
  - backend close 幂等关闭 session，并 shutdown curl_cffi stream executor。
- `services/protocol/conversation.py`
  - `ConversationRequest` 增加 `cancel_event`。
  - backend 接收 cancel event；metadata timeout 纳入 pre-conversation transient。
  - cancel 异常不重复 `mark_image_result(False)`；image/text backend 显式 close。
- `services/protocol/openai_v1_image_generations.py` / `openai_v1_image_edit.py`
  - 把 `cancel_event` 传入 `ConversationRequest`。
- `services/image_task_service.py`
  - progress callback 原子保存 `conversation_id`、当前 token 和 task DB 恢复字段。
  - hard timeout 设置 cancel，等待 1 秒宽限，记录 `runner_alive_after_cancel`。
  - 捕获会话时转 `timeout_pending`，保存 resume token 并后台续轮询；无会话才 mark-fail。
  - 迟到 progress 不再覆盖 hard-timeout 终态。
